- [ ] A reading group that does not follow kanji lands over the single preceding character instead of being dropped — frontend/app/src/lib/furigana.ts:47 !p2
  Claude annotates a word rather than a kanji run - e.g. `お願い《おねがい》します`, or an all-kana `ひらがな《ひらがな》`. Both pass `ClaudeTranslator#furigana_from`, whose only check is that stripping every `《…》` reproduces the translation character for character; it says nothing about where a group sits. `parseFurigana` fails KANJI_RUN (pending ends in `い`), falls through to the single-character fallback, and the pane renders おねがい as ruby over `い` alone with お願 plain beside it - a reading over the wrong base in a pane someone is learning from, which is what `annotateTranslation` refuses to do for a gloss-cut base ("missing is honest, wrong is not"). Caveat: reachability rests on the claim that the prompt does not constrain group placement, which the finder asserts rather than demonstrates; the doc comment's own defence ("a group always follows kanji") is likewise an assumption about model output that nothing tests.
  Fix: Drop the reading when the character before the group is not in the KANJI class, the way a cut base is dropped, and give FakeTranslator a kanji to annotate so the dev/CI path no longer needs a fallback that exists only to render `[JA]《ジェイエー》`.

- [ ] The auto-grow hook re-measures only on window resize, so a scrollbar appearing narrows the column and clips text — frontend/app/src/lib/useAutoGrowTextarea.ts:28 !p2

The page is now ~1,500 px tall, a classic scrollbar appears (Windows/Linux Chrome and Firefox), the column narrows ~15 px, and the rewrapped text needs another line or two that are clipped.
